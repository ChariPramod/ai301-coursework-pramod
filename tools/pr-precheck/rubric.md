# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Plan-context scope, non-goals, test plan and deviations paired with every diff hunk and the description; Plan fidelity in the evidence guide | The diff implements the stated repair within the plan or explicit, justified deviation notes. Both additions and omissions are accounted for. The description accurately states what shipped and what did not. An honestly disclosed partial delivery can pass when the plan/deviations and description agree; silent extra work, silent missing work or false fidelity claims fail. | required |
| Observable verification | Plan reproduction and test plan paired with candidate test evidence and the repo-facts check requirements; Test evidence | Evidence identifies the exercised behavior, inputs or scenario, commands/actions and observed results that distinguish before from after. Relevant repository checks have recorded actual outcomes. A concrete failed attempt or justified unavailable check disclosed with its reason is evidence, not a passing test; assess it under stated repository requirements. Generic “tests pass,” proposed future runs, or an unrelated green suite do not establish the repair. Do not require raw full logs when concrete commands and decisive results suffice. | required |
| Reviewable diff | Candidate unified diff, changed files and commit list read against the issue and plan; Diff quality | Every hunk serves the issue’s repair or necessary regression coverage. No debug output, abandoned code, accidental files, unrelated cleanup or broad formatting buries the change. A documented deviation explains necessary work but does not excuse unrelated debris. Judge contents, not commit count or diff length alone. | required |
| Accurate claims | PR title, description and checked boxes paired with diff, observed test results and stated limitations; Plan fidelity and Test evidence | Material claims about behavior, coverage, completed checks and readiness are supported by the package as a whole. Accepted-plan context and concrete recorded outcomes are evidence; missing details in thread highlights or excerpted code are not contradictions. Require a demonstrated conflict, not speculation about omitted callers/helpers, before declaring a claim false. An explicit routine formatting/checklist attestation counts without a separate log unless the repository asks for one; core behavioral verification still requires observable results. Failures, omissions and environment limits are disclosed without being labelled passes. No invented approval or test result. A truthful bounded shortfall is eligible to pass; disclosure does not replace all behavioral evidence or override a mandatory repository standard. | required |
| Repository standards and communication | Repo-facts template asks and contribution/AI policy, issue/thread requirements paired with candidate description; Standards and comms | Meets explicit applicable template, issue-link, contribution and disclosure requirements, with meaningful content rather than empty headings. Under a rule requiring all AI assistance to be disclosed, name tools and extent or explicitly state none; silence is unclear. Do not invent an AI policy, template or test requirement absent from the supplied facts. Report relevant maintainer direction faithfully and communicate without blame or demands. For a pre-opening draft, an unchecked CI box honestly marked pending is not a fabricated result; distinguish post-opening checks from checks executable now. | required |
| Navigable evidence | Description and test-evidence references | A reviewer can connect each material claim to its diff or decisive output without searching unrelated artifacts. | preferred |

## Verdict rule

Accept only when all required checks pass. A required fail or unclear produces reject. Preferred checks never change the verdict. Use unclear only when necessary evidence is absent or unverifiable; use fail for an observed contradiction. Explain the smallest missing fact or correction. A disclosed limitation can satisfy a check whose condition permits it, but honesty alone never waives the other checks.
