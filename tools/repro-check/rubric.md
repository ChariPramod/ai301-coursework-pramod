# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Specific claim | Candidate claim comment read against the issue title, body, and thread; Comms in the evidence guide | Names the issue's concrete trigger or symptom and a relevant investigation or report already performed or proposed. Ownership language alone or a generic offer is insufficient. Commitments are limited to investigation/reporting, without guaranteeing a fix or deadline. | required |
| Environment | Repro report's environment record compared with the issue's target and repo-facts template asks; Environment in the evidence guide | Identifies the tested project version or commit and the runtime, OS, browser, configuration, or dependency versions needed to interpret this behavior. Relevant deviations from the target are stated and the conclusion stays within the tested environment. Missing irrelevant details do not fail this check. | required |
| Runnable steps | Repro report's commands or UI actions, inputs, fixtures, and starting state; Steps in the evidence guide | A stranger can reach the tested trigger from the stated starting state using the supplied inputs and setup instructions, without guessing a consequential command, setting, file content, or action. Linked public fixtures count when available in live mode; eval uses only the bundle's supplied evidence. | required |
| Target and evidence | Repro report's actual output, logs, screenshot descriptions or test results read against the issue's trigger and expected/actual behavior; Behavior shown in the evidence guide | Concrete observations demonstrate an attempt at the issue's actual trigger and distinguish its reported failure from an adjacent failure. A reproduced claim requires evidence of that failure. A cannot-reproduce conclusion passes when evidence shows the relevant attempt and observed nonfailure; an unrelated setup error alone is not a completed attempt. | required |
| Honest outcome | Claim and repro assertions compared with the report's artifacts, tested environment, and issue context; Honesty in the evidence guide | States reproduced, cannot reproduce, or the bounded observed result consistently with the evidence. Separates expected from observed behavior and inference from observation; no unsupported certainty about cause, scope, affected platforms, or successful reproduction. | required |
| Repo conventions and communication | Both comments compared with repo-facts reporting requirements and contribution/AI policy, or live repository docs; Comms in the evidence guide | Meets applicable explicit reporting and disclosure requirements and communicates an independent, issue-specific account without blame, demands, or piggyback confirmation. When the repository explicitly requires disclosure of all AI assistance, the outgoing text must state the tool and extent of assistance, or explicitly state that none was used. Silence leaves compliance unclear and holds the package; do not infer no AI use from silence. No unstated policy is invented. Equivalent wording/organization is sufficient unless the repository explicitly mandates a form. | required |
| Navigable proof | Steps and artifacts in the repro report | Each artifact can be connected to the action and result it supports without searching unrelated material. | preferred |

## Verdict rule

Accept only when every applicable required check passes. A required fail or unclear means reject; preferred results never change the verdict. Unclear means necessary evidence is absent or unverifiable, and the summary must identify what would resolve it.

For a live claim-only draft, apply Specific claim and Repo conventions and communication to the claim. Mark report-dependent checks unclear with evidence `not yet applicable: claim-only draft` and exclude them from the verdict. Evaluate a claim's factual assertions against available evidence, but do not demand reproduction before a prospective claim. For a full package or eval bundle, apply every check. An evidenced cannot-reproduce is eligible for accept on the same evidence standard as a reproduced outcome. Check voice-guide.md separately in live mode and quote any broken rule.
